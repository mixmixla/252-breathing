# 测试策略 · 2026-09-12 版（开局链重做 + MC 操作对标 + 渲染管线升级）

> 版本范围：OPEN_ITEMS §8–§13 全部改动。
> QA 结论先行：**本版本最大的质量风险不是"旧功能坏了"（22 道门禁每轮全绿已覆盖），
> 而是"新能力从未被证伪"——选址器、村庄避让、潜行防坠边、防嵌墙、HudText 缓存、
> 移动平滑全部只有"能跑"，没有任何一条性质断言。** 本策略的核心就是把它们补上。

## 2. 测试金字塔

### L1 · 既有门禁（每轮构建必跑，出口 22 全 0）

已覆盖且继续有效：确定性四指纹、物理 STEP/WALL2、流式窗口、存读档黄金、NPC/社会/巨构/物质自洽、菜单语义、音频纯度。
**注意**：指纹已换基线两轮（21a2de→7fee9f→437234；NPC 390fbd→856032），基线演进记录在 event_log，回溯对照看历史条目。

### L2 · 门禁补强（本策略的核心交付，按优先级）

**P0（版本出口前必须落码，均可无头自动化）**

| 新门禁 | 断言的性质（非"能跑"） |
|---|---|
| **SpawnPickTest** | ①确定性：同种子两次 findSpawn 结果逐字节一致；②平坦性：落点 3×3 邻列高差 ≤1 且上方 2 格净空；③边界：SY=40 小世界（inBounds 收紧）仍能返回合法坐标或回落中心，永不越界；④可达性：落点 3×3 内至少 1 列 GRASS 地表（防选进石头坑=死选址） |
| **SneakTest**（并入 PhysicsTest） | ①防坠边：独立悬崖平台（1×N 走廊悬空），sneak=true 向边缘移动 → x 停在平台内、永不越界；②正常性：sneak=false 同路径不受限（防坠边不误伤普通移动）；③减速：sneak 单帧位移 ≈ 0.45× 正常位移；④签名兼容：旧 5 参 physicsTick 行为与 sneak=false 完全一致（已有 STEP/WALL2 断言继续锁定） |
| **BeastRefugeTest** | ①避让：玩家置于村心 10 格内，强制 spawn 判定 → 任何生成的 beast 与村心距离 > VILLAGE_RADIUS（庇护所性质）；②节奏：GRACE_TICKS 内 beasts 恒空；③确定性：同种子 spawn 序列可复现（重掷流确定性） |

**P1（建议抽纯方法后补测）**

- `blockTouchesPlayer` 从 Game 抽到 Player（静态几何函数）→ 测：玩家盒与脚下/头顶/邻格相交矩阵（9 格穷举），断言"脚下方块判定为相交、正前方半格判定为不相交"。
- HudText 缓存等价性：同一文本×位置×颜色，缓存路径与直接 Font/CjkFont.draw 的顶点序列逐 float 一致（可在无头环境测 Font 层，跳过 GL）。

**P2（记录，暂不做）**：罗盘方位数学（纯 UI）、横幅文案、FOV 平滑。

### L3 · 手动探索测试（QA 主战场，Game 层不可自动化的部分）

按"一次跑图、五段聚焦"组织（约 30 分钟）：

1. **开局段**：新档出生 → 确认①开阔平地无围困 ②庇护所横幅出现 ③6 秒无敌刷 ④村民在视野内 ⑤罗盘 N/E/S/W 滑动、金点字母、绿点方向。
2. **移动段**：①起手/急停有无惯性（应柔和）②Ctrl 疾跑 + FOV 拉伸 ③Shift 潜行走上悬崖边缘——**必须被拦住** ④潜行中 Ctrl 不应触发疾跑（互斥）。
3. **交互段**：①右键对自己脚下 → 应 DENY 拒绝（防嵌墙）②按住右键垫脚 2 格 → 连续放置 ③按住左键连续挖 ④1-5 切方块。
4. **昼夜/庇护所段**：挂机到入夜 → 「夜幕降临」横幅 + **村庄内无 beast 刷出**；走出村庄半径 → beast 开始出现；回村 → 不再新增。
5. **异常段**：①游戏中切窗 30 秒再回 → 不卡键、sim 曾暂停 ②TAB 锁定 → LOCK ON toast + 镜头接管，再按解除 ③拖拽窗口大小 → HUD/FOV 正常。

### L4 · 回归验收

- VALIDATION_CHECKLIST（2026-09-10 版）中与本版本无关的旧验收项（村志/音频/神殿）照常回归；
- 今晚各轮"待目视验收"（OPEN_ITEMS §8–§13 尾部）已全部汇总进上文 L3，不再散读。

## 3. 专项测试

| 专项 | 内容 | 方法 |
|---|---|---|
| **存档兼容**（P0） | 旧档（选址器之前生成）+ 新代码：读档不得重算选址、不得重摆村民、300 tick 演化自洽 | 用今晚更早版本的 save/world.sav（若无则构造：旧代码快存一份存档文件留底）新代码 F10 读入 + 挂机 5 分钟无异常 |
| **性能基准** | tick 耗时不高于基线 4.56ms/tick@160（±10%）；HUD 缓存收益：操作卡常驻时帧时间下降 | **先预热 100+ tick 再测**（冷启动 JIT 假象纪律）；F3 对照 DRAW/帧时间 |
| **CJK 降级** | 字体缺失环境下：横幅/操作卡/受困提示走 ASCII 分支不崩溃、不显示问号 | 临时改 CjkFont candidates 首个为不存在字体（或信 render_diag.log 的 CJK 状态行） |
| **长挂机稳定** | 2 小时挂机（村庄庇护所下 beast 长期不刷路径 + 缓存两帧清理路径） | 内存不增长（HudText CACHE 收敛）、无 GC 风暴、帧率平稳 |

## 4. 出口准则（Definition of Done）

1. 22 道门禁全绿 + **P0 三个新门禁落码并全绿**；
2. L3 五段手动探索全部通过（每段记录 PASS/FAIL + 截图）；
3. 存档兼容专项实测通过（旧档可读、可玩、演化自洽）；
4. 性能基准不劣化（±10% 内）；
5. 无 P0/P1 级 bug 未决（P2 记 OPEN_ITEMS 可带病发布）。

## 5. 建议执行序

1. **我方（AI）**：落码 P0 三个新门禁 + 跑全量（一次构建完成）；
2. **用户（你）**：按 L3 五段跑图 30 分钟（这是 Game 层唯一的质量证据来源）；
3. 双方汇合：FAIL 项进 OPEN_ITEMS 排修复，PASS 则本版本出口。
