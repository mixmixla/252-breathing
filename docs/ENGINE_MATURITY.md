# 引擎成熟度评估 · Engine Maturity

> 你问：**引擎的搭建什么时候完善？**
> 这份文件给一个可验证的答案，而不是"快了"。

---

## 1. 判据：不看功能数量，看"改不改引擎"

通常的误区是拿"功能清单"衡量引擎。对**这个项目**而言，正确的判据只有一条：

> **当你要加第 100 个技能 / 第 50 个敌人 / 第 10 套玩法时，需不需要动引擎代码？**

如果不需要 —— 引擎对这个用途就**够用了**。如果需要 —— 缺什么就补什么，且只在缺的地方补。

这个判据的好处：它是**可测的**（加一个东西，看改了哪些文件），也是**可止的**（不必等到"功能齐全"）。

## 3. 三个里程碑

| 里程碑 | 含义 | 状态 |
|---|---|---|
| **M1** | **加内容零改引擎** —— 内容/玩法/系统三层平台打通 | ✅ **已达成** |
| **M2** | **手感达标 + mod 可加载** —— 动作系统打磨（C 批）+ MOD 支持（G 批） | ✅ **已达成**（C 批六项 + G 批全落） |
| **M3** | **大世界流畅** —— 跨图流式分帧 + 实体查询去 O(N²) | ✅ **已达成（2026-09-14）**：单帧最坏 508ms → **11.5ms（44x）**；四基线指纹逐字节不变；当时 46 道门禁全绿（**现行 53 道**，2026-09-18 加 `SHADERGLSL`） |

**另有一条不属于 M 系列的线：N 系列（确定性锁步联机）** —— N0 可移植性硬化 ✅ / N0b 跨 JVM 实证 ✅ /
N1 输入编解码 ✅ / **N2 快照·回滚收口 ✅（2026-09-14）** / **N3 真实 UDP 锁步 ✅（2026-09-14）** / **N4 预测回滚 ✅（2026-09-14）**。

**M1 / M2 / M3 全部达成。** M3 属于"规模与体验"，不是"能力缺失"——

而且关键点在于：**M3 完成之前，内容依然可以一直加**。这就是三层平台建好之后的红利。

## 4. 诚实的结论

**引擎永远不会"完善"。** MC 十四年了还在改；泰拉瑞亚的引擎也在持续动。
追求"完善"是一个没有终点的目标，容易被它拖住而不敢加内容。

对这个项目，正确的说法是：

> **M1 / M2 / M3 都已过 —— 现在加任何内容都不需要改引擎，做大世界也不再卡顿。**
> **剩下的是"如果要做更远的视距 / 千级实体同屏，还要再动一次引擎"。**

所以排期上我建议：

1. **先让内容长起来**（数据驱动，全部走 JSON）—— 验证平台真的能承载"源源不断"
2. **等内容的真实痛点出现时，再动下一轮引擎优化** —— 因为那时候才知道该优化哪个指标

**用内容反推引擎，而不是先造一个"完美引擎"再想装什么。** 这也是泰拉瑞亚和 MC 的实际路径。
