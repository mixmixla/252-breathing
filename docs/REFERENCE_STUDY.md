# 对标学习清单 · Reference Study

> 你点的五款游戏 + 我们动作系统的短板，逐条拆成「学什么 → 落在哪一层 → 现在缺什么」。
> 核心判断：**下面九成的东西都能落在内容层/玩法层，不用碰仿真内核** —— 这正是平台的价值。

## 1. 赛博朋克 2077 —— 捏脸

**学什么**
- **分层可组合**：脸型/五官/发型/义体/服装各是一层，层内多选，组合爆炸出个性
- **参数连续**：不是纯枚举，很多是滑杆（鼻梁高度、下颌宽度）→ 每个角色都不一样
- **即时预览**：改了立刻看见

**我们的落点**：`assets/content/models/*.json` 扩展成**外观层定义**
```
"layers": [
  {"slot":"head",  "parts":[{"id":"round"},{"id":"long"},{"id":"square"}]},
  {"slot":"hair",  "parts":[...], "tint":[0.1,0.1,0.1]},
  {"slot":"gear",  "parts":[...]}
],
"params": {"jawWidth":[0.6,1.4], "heightScale":[0.9,1.15]}
```
配 `assets/content/appearance/presets/*.json`（预设脸）。

**成本**：中等（主要是关节网格/部件的方块化美术 + 一个捏脸 UI 界面）。

---

## 2. DNF —— 技能组

**学什么**
- **技能树**：前置技能 + 点数分配 → 不同加点 = 不同打法
- **连招取消**：技能 A 的收招段可以被技能 B 取消 → 手感流畅的关键
- **技能等级**：同一技能可强化

**我们的落点**：新增 `assets/content/techs/tree_*.json`（树结构）+ `skills/*.json` 加字段
```
"requires": ["flame_burst@2"],     // 前置技能与等级
"costPoints": 1,
"cancelInto": ["gale_step"],       // 可被哪些技能取消（连招）
"cancelWindow": [0.18, 0.42]       // 可取消的时间窗（秒）
```

**成本**：低—中（数据驱动为主；取消窗需要动作系统支持，见 §6）。

---

## 3. 饥荒 / 缺氧 —— 科技链

**学什么**
- **配方图**：科技不是线性，是**有向图**（多前置 → 一个解锁 → 解锁多个）
- **科技机**：需要"靠近某设施"才能制作（空间约束）
- **缺氧式的产线**：资源 → 中间品 → 成品，链条越长越有成就感

**我们的落点**：新增 `assets/content/techs/*.json`
```
{ "id":"smelting", "requires":["mining@1","kiln"], "unlocks":["iron_bar","steel"],
  "station":"kiln", "cost":{"coal":2,"ore":3} }
```
`World.skills` 已经是天然的"已解锁标记"集合（`addSkill/hasSkill`），**且不进指纹**。

**成本**：低（纯数据 + 已有 `hasSkill` 支撑）。**这是投入产出比最高的一项。**

---

## 4. 塞尔达 —— 探索引导与攻防流程

**学什么**
- **三角法则**：地标吸引视线 → 玩家自发前往（我们已有巨物剪影，天然适配）
- **引导不靠箭头**：靠视觉地标 + 罗盘微光（我们已有金点/绿点罗盘）
- **盾反 / 完美闪避 → 子弹时间**：高风险操作给高回报
- **耐久与资源循环**：武器会坏 → 逼迫尝试新东西

**我们的落点**
- 探索：`ShrineSystem` 已有祭坛；补「视线可达性」——把地标加入罗盘（已有金点）
- 攻防节奏：`anim` 的 `events` 帧已在（攻击命中帧 0.28s）→ 补**完美闪避窗**（`roll` 前 0.2s 无敌 + 反击加成）
- 耐久：`items/*.json` 加 `durability`（需背包，P3）

**成本**：低—中。

## 5. 上古卷轴 5 —— 用中学成长

**学什么**
- **不做"经验条"，做"熟能生巧"**：用剑→剑术涨；被打→重甲涨
- **流派分化**：潜行弓 / 毁灭法 / 双手剑，玩法差异极大
- **技能树 + 等级门槛**：perk 需要属性等级达标

**我们的落点**：`rules/*.json` 的 ECA 天然适配
```
{ "event":"repel", "from":"combat",
  "if":[{"check":"SCALAR_AT_LEAST","name":"skillSword","value":10}],
  "then":[{"type":"DIALOGUE","id":"Sword mastery up"}] }
```
`buffs/*.json` 做流派增益。

**成本**：低（纯规则）。

## 6. 泰拉瑞亚 —— 平台与 MOD 生态（真正的榜样）

**为什么它比前面五个都更值得学**
前面五款各有一个出色的**机制**；泰拉瑞亚证明的是一件更大的事：
**一个结构清晰的引擎 + 一堆数据表 + 一个开放的扩展接口 = 一个能长十五年的内容宇宙。**
4000+ 物品、400+ 敌人、30+ Boss —— 绝大多数只是"同一套框架下的数据"。

| 机制 | 说明 | 我们的落点 |
|---|---|---|
| **进程阶段（progression phase）** | 打完 Boss → **世界进入下一阶段**（Hardmode），全局规则改变：新敌种、新矿脉、新事件 | `World.skills` 做标记 + `presets` 参数/`disablePhases` 覆盖 + `techs` 图 |
| **事件式入侵** | 血月 / 哥布林入侵 = 「时间 + 条件」触发的全局事件 | `rules` 的 ECA + `World.events` 事件总线（**已具备**） |
| **装备分层** | 每个阶段一套装备，用上一阶段材料造 | `techs.cost` + `items` |
| **统一 ID 表 + 相互引用** | 所有内容有稳定 ID，内容之间靠 ID 引用 | `ContentRegistry` 以文件名作 ID（**已具备**） |
| **tModLoader** | mod = **代码 + 数据**，通过稳定接口（ModItem / ModNPC / ModWorld）挂进引擎 | 我们的分工：**内容写 JSON；新机制写 `GameplayModule`（代码）** |

### 关键启示：mod 不是"纯数据"，是「数据 + 扩展点」

泰拉瑞亚的 mod 作者写 C#，因为**新机制必须写代码**。所以"万物可配置"的准确表述应该是：

> **万物可声明；机制需编码一次，之后无限复用。**

这恰好就是我们已经建好的三层结构：

```
数据层   assets/content/**        ← mod 作者只改这里（技能/粒子/科技/剧情/敌人）
模块层   GameplayModule           ← mod 作者需要新机制时写这里（一次编码）
引擎层   core/ + render/          ← 我们维护，提供稳定接口
```

### 因此：P4（MOD 支持）应当提升优先级

"什么都有、mod 又多"不是内容量的结果，而是**扩展接口开放**的结果。要做的工程前提：

1. **内容包加载**：`mods/*.zip` → 解压出 `content/`，与官方内容合并
2. **覆盖优先级**：mod 可**覆盖**同名 ID（同 ID 后加载者胜，或显式 `override: true`）
3. **可选代码扩展**：内容包可带 `modules/`（声明式）+ 可选 jar（机制扩展）
4. **冲突报告**：两个 mod 改同一 ID / 引用悬空 → 启动时列出（复用 `ContentRegistry` 的校验）

> MC 同理：它的长久生命力来自数据包 + mod 加载器，而不是原版内容量。

## 7. 动作系统打磨清单（曾是最粗糙的部分）

现状：`Clip` 只有关键帧线性/smoothstep 插值 + `events` 帧。**C 批已补齐全部六项**（详见
`docs/UE5_ANIM_BENCHMARK.md` —— UE5 源码对标审计）。

| 缺口 | 说明 | 状态 |
|---|---|---|
| **取消窗（cancel window）** | 收招段可被下一动作打断 | ✅ `AnimController`（C 批①） |
| **判定帧（hitbox timing）** | 命中判定只在特定帧生效 | ✅ `AnimController` 判定帧唯一性（C 批②） |
| **连招链（combo chain）** | 轻击 1→2→3 段，各有独立时机窗 | ✅ `AnimController.combo[]`（C 批②） |
| **根运动（root motion）** | 位移由动画驱动而非代码 | ✅ `RootMotion`（C 批③ · UE5 对标） |
| **混合树（blend tree）** | 走↔跑按速度混合，而非二选一 | ✅ `BlendSpace`（C 批③ · UE5 对标） |
| **上半身遮罩** | 边跑边挥砍（上下半身独立） | ✅ `BoneMask`（C 批③ · UE5 对标） |

门禁：`ANIM`（插值/事件/坐标）、`ANIMCTL`（战斗语义）、`COMBAT`（状态机接线）、
`ANIMLAYERS`（C 批③ 三原语 + 确定性 + 零漂移）。

## 8. 分批路线（按投入产出比排序）

| 批次 | 内容 | 层 | 成本 |
|---|---|---|---|
| **A（最划算）** ✅ | 科技链 `techs/` + 用中学成长 `rules/` | 内容/玩法 | 低 |
| **B** ✅ | 技能树 + 前置/点数（`skills` 加 `requires`） | 内容 | 低 |
| **C** ✅ | 动作系统打磨：取消窗 + 判定帧 + 连招链 + root-motion + 混合树 + 上下半身遮罩 | **引擎** | **中高** |
| **D** ✅ | 探索引导强化（完美闪避✅ / 地标入罗盘✅） | 玩法/引擎 | 中 |
| **E** ✅ | 背包 + 物品耐久 + `GRANT_ITEM` 接通 | 内容+引擎 | 中 |
| **F** ✅ | 捏脸（外观分层 + 参数 + UI） | 内容+引擎 | 中高 |
| **G** ✅ | **MOD 支持**：内容包加载 / 覆盖优先级 / 冲突报告（泰拉瑞亚式扩展点） | 引擎 | 中 |

**建议顺序**：A ✅ → B ✅ → D ✅ → G ✅ → **C ✅（六项全落地）** → E ✅ → F ✅。
A/B/D 全是数据驱动、当天可见效；**G（MOD 支持）是"万物"这个目标的工程前提**——接口一开，
之后新增内容才真的"源源不断"；C 是硬骨头但决定手感（已按 UE5 对标补齐六项）；E 补上
`EffectSink` 的物资缺口；F 最重最独立，已收尾。

> 注意：C 曾改动 `anim` 的核心语义 —— 已补**动作门禁**（`ANIMCTL` 取消窗时序/连招链合法性/判定帧唯一性、
> `ANIMLAYERS` 三项新原语 + 确定性 + 零漂移），"手感"这种主观的东西现在有断言挡着。
