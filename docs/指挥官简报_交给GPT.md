## 0. 一页纸（先看这个）

### 一句话判定

> **这是一个「工程完成度异常高、游戏完成度偏低」的项目。**
> 它的地基（确定性内核 + 88 道等价门禁 + 内容平台 + 真实 3D 渲染管线 + 联机锁步）已经达到**独立游戏引擎入门水准**；
> 但坐在里面的玩家**只有 1 个任务、1 种野怪、3 个技能、0 首音乐**，NPC 会走会饿但**不会劳动 / 交易 / 合成**。
> 所以：**性能不是瓶颈，内容与玩家可见的循环才是。**

### 三条最重要的结论

| # | 结论 | 依据（实测） |
|---|---|---|
| 1 | **性能达标，别乱优化** | 稳态 **144 fps**（`dirty=0 / mesh=0/0`）；仿真 tick 已优化到 **1.32 ms**（≪ 16.67 ms 帧预算）。唯一的性能缺口是**冷启动 13.5 秒只有 10~30 fps**（进场装修太慢）。 |
| 2 | **最大的短板是内容与"玩家可见的呼吸"** | 内容资产：`quests=1`、`beasts=1`、`skills=3`、`techs=4`、`reactions=7`、`buffs=1`、**音乐 0**。而引擎侧有 **99 个系统 / 316 个内容文件 / 133 个物品 / 131 种材料**。**管道远大于货量。** |
| 3 | **护城河是"零漂移门禁体系"，不是玩法** | 88 处 `*_EXIT` 全 0；`simHash=e7d033aec2a74d0f` 是回归判据。**任何改动都必须先证明没破坏它。** 这套方法（先量再改 / 等价门禁 / 诚实边界）是这个项目最值钱的资产，比任何单个玩法都重要。 |

### 现在最该做的三件事

1. **冻结基线**（清 `out/` 全量构建，确认 88/88 全 0 + simHash 记录在案）—— 没有可信基线，后面全是假绿。
2. **修冷启动**（13.5 s → 目标 < 4 s）—— 这是**唯一一个玩家每次启动都会遇到的体验缺陷**，且已有现成诊断工具。
3. **把 NPC 的劳动闭环做出来**（`Decision` 的 `GATHER/CRAFT/TRADE/STATION` 目前是**有常量、无实现**）—— 这是"会呼吸的世界"这一 USP 从宣传语变成可玩事实的关键一步。

### 最不该做的三件事

1. **不要重写引擎 / 不要换渲染架构 / 不要上 Lumen、Nanite、TAA、DOF**（项目已明确劝退，收益低风险高）。
2. **不要为了"更快"削弱或跳过任何门禁** —— 那 88 道门禁是正确性保障，是过去踩过的坑凝固成的。
3. **不要动 `play/` 下的 JS 三形态基线**（`golden.json` 里 `winRate 0.75` 是另一套被锁死的系统，Java 版与它无关）。

### Phase 0 · 校准与防伪（先做，0.5 天）

- **目标**：得到一个"当前代码库真的是绿的"的可复现证明。
- **做法**：

  cd java/breathing-world
  rm -rf out                      # 关键：防"编译失败⇒门禁跑旧 class⇒静默假绿"
  BW_KEEP_OUT=1 python build_runner.py

- **禁止**：不允许"看到个别红灯就当环境 flaky 跳过"。历史上有**真 bug 被这样掩埋了五批**。

### Phase 1 · 止血：把"进场体验"修好（1~2 天）

#### T1.1 定位冷启动 13.5 秒的重复烘焙（🔬 只测量，先不改）
- **已知**：`-Dbw.fpsdiag=1` 每秒输出一行，含 `fps / dirty / mesh=inflight/threads / built`。
  实测 `built=1484` 对 **100 块**窗口 ⇒ 高度可疑。
- **做法**：
  1. 在 `Chunk`/`MeshBuilder` 加一个**每块重建次数直方图**（`Map<chunkKey,int>`，仅诊断开关下开启），启动后 dump top-20。
  2. 同时记录**每个 chunk 被标脏的原因**（枚举：初始生成 / 光照变化 / 阴影卷 / 平移条带 / 编辑）。
- **交付物**：`proof/mesh_rebuild_census.txt`（谁在反复标脏，占比多少）。
- **验收**：能一句话说清"1484 次里 X% 来自 <原因>"。
- **禁止**：**不许在没拿到 census 之前就动手改**。这是本项目最核心的纪律 —— 历史上"先改后量"至少踩过 5 次，包括"用总时长反推分段耗时"这种基础错误。

#### T1.2 把首屏可玩时间压到 4 秒内（依赖 T1.1）
- **目标**：从进程启动到 `dirty==0 && mesh inflight==0`（即"可以流畅操作"）由 **13.5 s → < 4 s**。
- **候选手段**（**必须先取 census，再择一或组合，每项都要 A/B 证明**）：
  - ① 修掉重复烘焙的根因（若 census 指向某条脏标记链）；
  - ② 首帧只同步烘焙"视锥内最近 N 块"，其余走异步 + 加**确定性加载态遮罩**（不是假黑屏）；
  - ③ 网格线程 4 → 8（`mesh=4/4` 显示当前 4 线程 4 并发）；
  - ④ 预生成阶段降低 Y 方向分辨率/跳过不可见列。
- **验收**：`proof/boot_fps_after.txt` 显示 `dirty==0` 到达时间 < 4 s；**且 88 门禁全 0、simHash 不变**（若动了世界生成顺序则必须走"有意演进"流程并明确记录）。
- **禁止**：不许通过"减少世界尺寸 / 降低视距 / 关掉光照"来换时间 —— 那是把病藏起来。

#### T1.3 移动中的流式帧率实测（**空白项，必须补**）
- **已知**：稳态 144 fps 是**玩家静止**时。**移动中的流式加载帧率从未测过。**
- **做法**：写一个无头/半无头驱动（可复用 `tools/qa_snap.py` 的 classpath 拼法），脚本扮演"前进 20 格 → 停 2 s"×10 轮，全程 `-Dbw.fpsdiag=1`。
- **交付物**：`proof/stream_move_fps.txt` —— 报告 p1 / p50 / p99 帧率与最大单帧耗时。
- **验收**：给出"移动中最差帧率 = ? fps"，并指明是否触发 `shifting=true`。
- **为什么重要**：`MESHSHIFT` 门禁证明的是**网格等价**，不是**帧率**。这两者不能互相代替。

### Phase 2 · 内容与循环：让游戏"有得玩"（1~2 周，**主战场**）

#### T2.1 NPC 劳动闭环 —— 把 `Decision` 的预留标签变成现实（🔴 最高价值）
- **目标**：NPC 从"会走会饿的装饰"变成"**会采集、会合成、会交易、会守摊**的工匠"。
- **现状**：`Decision.choose()` 只产出 `FLEE/DRINK/EAT/WANDER/IDLE`；`GATHER/TRADE/CRAFT/STATION/MEDITATE` 是**无生产者无消费者**的常量。
- **做法（建议切分）**：
  1. **生产者**：在 `Decision.choose()` 中按优先级插入新分支（携带需求的 NPC → `GATHER`；村仓有料 → `CRAFT`；有人流 → `STATION`）。随机只走 `simStream(name)`。
  2. **消费者**：在 `NpcSystem` 的执行层补齐对应动作（采集写村仓、合成走 `RecipeBook`、守摊挂 `PolitySystem`）。
  3. **可见性**：动作必须**看得见**（姿态动画 + 头顶状态 + 村志记一笔）。
- **验收**（四条全要）：
  - ① 每个新标签都有**真实生产者 + 真实消费者**（对照 `docs/UNIMPLEMENTED_2026-09-16.md` 的"空转参数"教训：**"参数传了" ≠ "行为发生了"**）；
  - ② 确定性：新随机全部走 `simStream`，无 `Math.random` / `nanoTime`；
  - ③ 门禁：`NPCD` 门禁扩充断言（含"新标签可达"负例对照）；
  - ④ 88 门禁全 0、`simHash` 变化必须被**显式声明为"有意演进"**（NPC 行为变了，指纹该变就变 —— 但要写清楚是**有意**的）。
- **禁止**：不许把新行为做成"只有调试开关下才跑"的摆设。

### 6.4 已知陷阱（**读这一段可以省一天**）

1. **别用 `javac ... | head -N && echo OK` 判编译** —— 管道退出码是 `head` 的，**javac 失败也会打印 OK**。正确：`javac ... > log 2>&1; echo "rc=$?"`。
2. **CORE 编译失败会出现"静默假绿"** —— 门禁跑旧的 `out/`，标签总数塌到个位。存疑先 `rm -rf out`。
3. **`core/systems` 包里的 `System` 会遮蔽 `java.lang.System`** —— `World.java` 里必须写 `java.lang.System.out`。
4. **门禁 classpath 不含 NATIVES**（只有 SHADERGLSL/MESHASYNC/MESHSHIFT 挂）—— 跑 `memAlloc` 会 `UnsatisfiedLinkError`。
5. **裸 `new World(...)` 不带系统** —— `tick()` 的系统循环跑 **0 个**。等价性探针必须用真 `Simulation` 驱动。项目曾因此发现 4 条等价探针是**空转的**。
6. **门禁必须有失败退出码** —— 只打印 FAILED 却 `exit 0` 就是假绿。
7. **headless 下 `World.materials` 默认是空存根**（density 全 20 兜底）—— 探针/门禁必须显式 `ContentRegistry.load(new File("assets/content")).materialBook()`，并加自检断言防假账。
8. **GLSL 内联字符串是单行 Java 字面量** —— 注入脚本写换行必须用 Java 转义 `\\n`（两个字符），Python 写 `\n` 会插真换行、截断字面量。
9. **防重复注入守卫别用宽匹配** —— `"uDither" in s` 会命中 Java 字段名；要用带 `uniform float uXxx;` 的精确串（`bw_patch_*.py` 范式：字节级替换 + "必须命中 1 次"硬断言）。
10. **`play/_ci_guard.js` 在本类沙箱跑不通**（spawn node 子进程遇到 `EBUSY`）——会报告 20 项**假漂移**。沙箱里请**直接单跑各脚本**（`_verify_baked_3d.js` / `_soak_3d.js`）。这是环境限制，不是引擎问题。
11. **bash 里调 Java 的路径必须用正斜杠** —— 反斜杠会 `rc=127`。
