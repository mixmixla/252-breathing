# Art Bible · 会呼吸的世界（Java LWJGL3 版）

> 视觉真理来源（source of truth）。所有渲染层改动（方向光 / AO / 雾 / 描边 / 粒子 / 植被风 / 接触阴影）必须对齐本文件。
> 原则：MC 体素 × Elden Ring 打击感 × 塞尔达探索感；"会呼吸"= 有重量、有光照、有生命。
> 全部为纯渲染层，不进 `World.hashState()`，四道零漂移门禁（DETERMINISM/ZERO-DRIFT/PHYSICS/STREAMING）不受影响。
> **创意权威见 `docs/CD-PILLARS.md`**：本文件 4 视觉支柱是创意支柱 **P1 世界活着** 的**美术执行层**，从属于创意方向，不得反向定义游戏身份。

## 1. 视觉愿景（Visual Pillars · 执行 P1 世界活着）
- **Grounded（落地）**：方块有 AO 与接触阴影，角色/敌兵脚下有软影，世界"踩得住地"。
- **Atmospheric（氛围）**：渐变天空 + 距离雾，远景融进天色，纵深与"远方有未知"的召唤感。
- **Breathing（呼吸）**：植被顶点风动、粒子、受击屏震/顿帧，世界"活着"。
- **Readable（可读）**：反相外壳描边让角色/敌兵/祭坛在低对比场景里跳出来；HUD 信息层级清晰。

## 3. 光照方向（Lighting Direction）
- 主光方向由 `DayCycle.lightDir` 按时相横扫（白天=太阳、夜里=月亮；`y` 恒 > 0，防整面全黑）。
- **AP3 双光合成**：`l = uAmbient + (1 - uAmbient) * (0.72 * lambert + 0.28 * hemi)`，其中 `hemi = 0.5 + 0.5 * N.y`（上半球受天光）。`uAmbient` 由 `DayCycle.ambient` 驱动（夜 0.26 → 正午 0.62）。**暗部不再“压死”成近黑**。
- 体素顶点法线由 `Chunk` 网格提供，worldShader 做 lambert；实体改用 flat `shader`（无法线依赖，规避 NaN）。
- **顶点 AO**：每顶点按相邻实心度算 4 级遮蔽 `T=[1.0, 0.80, 0.62, 0.42]`，烘焙进顶点色，强化角落"窝进去"的纵深。
- **AP3 每体素颗粒**：`col *= 0.94 + 0.12 * h31(floor(vWorld))`（世界坐标纯哈希 → 无纹理也有“材质颗粒”，打散大色块）。

## 4. 材质语言（Material Language）
- 方块体素、平涂饱和 MC 色；透明方块（叶/玻璃/水/雪/花）走 `opaque=false` 面剔除。
- 描边 = 反相外壳（Pass1 放大暗盒 + `GL_POLYGON_OFFSET_FILL`），角色/敌兵/祭坛统一这套语言。
- 植被（leaf/flower）标记 `Blocks.Block.wind=true`，渲染层做正弦顶点偏移模拟摆动。

## 5. 三项扩展视觉规格（本次落地）
### 5.1 方块 AO + 接触阴影
- AO：顶点级，3 邻居采样（两侧 + 对角），`occ=3` 满遮蔽规则，映射 `T` 表烘焙进顶点色。纯渲染，不改网格拓扑。
- 接触阴影：实体脚下水平软盘（径向 α 衰减，`α_max≈0.35`，半径≈0.5），`GL_BLEND` + 关闭深度写入；给出"重量"。

### 5.2 天空盒 + 距离雾
- 天空：全屏三角形 gradient shader，按屏幕 Y 从 horizon→zenith 插值；绘制于世界之前、关深度。
- 雾：worldShader FS 按 `dist=distance(vWorld,uCamPos)` 做 `f=1-exp(-density*dist)`，mix 雾色；密度 `0.012`。

### 5.3 植被风动
- 标记方块 `wind=true`（leaf/flower）。Chunk 顶点加 `aWind` 属性（0/1）。
- worldShader VS：若 `aWind>0.5`，`pos.x += sin(uTime*1.6 + x*0.35 + z*0.35)*0.09` 等三轴微偏，幅度克制（"呼吸"非"狂风"）。

## 6. UI 视觉层级（HUD Visual Hierarchy）
- 左上：HP 红条 / 体力黄条（最重要：生死）。
- 顶部：LV / SOUL / PROSP（成长与进度）。
- 中心：准星（ER 风四点刻线）。
- 横幅：LEVEL UP / ABILITY AWAKENED（事件高光，2~2.6s）。
- 提示：魂锻反馈 `STR +1` / `NEED MORE SOUL`（即时反馈）。
- 受击：屏幕红边 vignette；击杀：`SOUL +8` 弹出 + 灵魂粒子。

## 7. 零漂移铁律（渲染层守约）
- 一切随机/计时只走 `sim.world.fxRng` 或渲染层局部状态（`time` 累加器），绝不读/写仿真 RNG 或 `hashState`。
- 新增渲染属性（`aWind`）只加在 chunk VAO，实体 VAO 不启用 → 实体不摇摆、不被雾误伤。
- 任何 GL 视觉问题都**不**污染仿真结果，可放心在本机 `run-game.bat` 调参。

## 8. ART-PROG-3 · 三期打磨（2026-09-11，全部纯渲染层）

**触发**：本机验收截图暴露五点 —— ① `FLOWER` 洋红成片，像 missing texture；② 大色块无材质变化（纯色 × lambert）；
③ 单光 + 低环境光 → 背光面压死成近黑；④ 夜/雨浑浊、缺层次；⑤ 无暗角/调色。

| 手段 | 落点 | 参数 |
|---|---|---|
| **半球环境光**（key + hemi 双光） | worldShader FS | `hemi = 0.5+0.5*N.y`；`l = amb + (1-amb)*(0.72*key + 0.28*hemi)` |
| **每体素材质颗粒** | worldShader FS | `col *= 0.94 + 0.12*h31(floor(vWorld))` |
| **花田色盘** | `Chunk.vegTint`（**顶点烘焙**） | FLOWER 按体素哈希从 5 色盘取色（玫瑰/金盏/白/紫/珊瑚）；LEAF 仅 ±12% 明度抖动 |
| **夜/雨可读性** | `DayCycle.ambient` + `Game` | 夜环境光 0.20→**0.26**（上限仍 0.62，受第 14 道门禁约束）；雨压暗 0.25→**0.15**；夜色地平线抬亮 |
| **调色 + 暗角** | world + sky shader | 饱和 +6% / 对比 +6%；`gl_FragCoord` 径向暗角，四角 −20% |

**纪律与理由**：
- 位置哈希 `Chunk.hash01` 是**世界坐标的纯函数**，不读/不写任何仿真 RNG 或状态 → 全部门禁（当前 43 道）指纹逐字节不变。
- 暗角直接用 `gl_FragCoord.xy/uRes` 在 sky/world shader 内算，**不引入 FBO / 后处理 pass**（零新增 GL 对象，降低 shader 编译风险）。
- 花田色盘在**顶点烘焙**阶段写入顶点色，AO / 明度系数照常复合 → 不破坏 AO 语义；`Blocks.FLOWER` 基色降为兜底。
- **HUD 不受调色/暗角影响**（HUD 走独立 `hudShader`）→ 文字仍保持高对比可读。

| 维度 | 决定 |

### 9.2 巨物主义的五条美术语法（从 Elden Ring 提炼，必须全中）
1. **剪影优先（silhouette-first）**：天际线留一眼可辨的异形轮廓（断裂拱 / 独柱 / 斜塔），玩家 200 格外就认出「那边有东西」。
2. **重复产生体量**：不是一块巨石，是**上百个同形构件**（柱列 / 拱券 / 垛口）；重复次数本身就是尺度单位。
3. **断裂的跨（broken span）**：一个「没接上的拱」比完整更有巨物感——暗示「曾经横跨过」。
4. **尺度对比（scale reference）**：必须有**人形参照**——玩家 2 格、门洞 14 格、塔身 56 格。无参照即无「巨」。
5. **被吞噬（burial / overgrowth）**：半埋进地、被根须苔藓吃掉 → 「文明已逝」。参考 MC `TerrainAdjustment`（NONE/BURY/BEARD_THIN/BEARD_BOX）。

### 9.5 形态语法（完整但空旷版）
1. 剪影三段式：基座收分（1.6:1）→ 柱廊段 → 冠顶塔尖；远景只留轮廓也要能认出。
2. 柱列间距 7、柱高 28、全殿 **>40 根**；拱券半径 6、跨 12–14。
3. **唯一保留的「残」**：远景剪影里留一段「未接上的拱」（不破坏「完整」叙事，却给出「曾经横跨」的信息量）。
4. 巨人台阶每级 4 格（玩家需跳/冲刺才能上）→ 暗示原主非人。
5. 构件完整、金饰仍亮、中庭空置 → 「神已离去，殿宇仍新」。

## 10. 火光照明（Fire Emissive Light）· P2-2 配套（2026-09-16）

**触发**：P2-2 火杠杆落地后，玩家放的火在夜里是一团**不亮的**色块——块光 BFS 原先只从 `LAMP` 取源，`FIRE` 不发光。燃烧的森林/火堆因此毫无存在感，"火"缺了最直觉的一半。

| 手段 | 落点 | 参数 |
|---|---|---|
| **FIRE 成为块光源** | `World.computeLight` | 新增第二类源：`FIRE_LIGHT_R = 9`（vs `LAMP` 的 `LIGHT_R = 14`） |
| **火是局部暖光而非照明灯** | 同上 | 半径更小 → 火格 `lightAt = 9/14 ≈ 0.64`，逐格衰减、9 格外归零；`LAMP` 仍 1.0 满强度 |
| **索引新鲜度修复（既有隐患）** | `World.computeLight` 开头 | 补 `ensureIndex()`：该函数直接读 `typeCells[LAMP/FIRE]`，而方块索引是**惰性增量**的 —— 不先应用增量会漏掉刚放下的灯/火（LAMP 同吃这口） |

**纪律与理由**：
- `lightGrid` 是**渲染派生缓存**：不进 `hashState`、`World.tick` 永不触碰（`computeLight` 仅由渲染线程调用，`Game.java:2529`）→ **全部门禁指纹逐字节不变**（本次实测：48 道 `*_EXIT` 全 0、基线全等）。
- 火光的暖色与强度由 worldShader **既有**的 `vLamp` 项承担（`col += tx.rgb*vCol*vLamp*vec3(0.60,0.42,0.18)*(1-uAmbient)*1.5`）—— **未改一行 GLSL**，零 shader 编译风险（无 GL 沙箱下的第一纪律）。
- 火光随火蔓延**实时**更新：`setBlock` 置 `lightDirty` → 下一帧 `computeLight` 重算。
- 实测（一次性探针，已删）：火格 0.643 / +1 格 0.571 / +4 格 0.357 / +12 格 0.000；`LAMP` 1.000 且与火**互不覆盖**。

**后续（待本机目视 / 截图后再调，不凭感觉改）**：① 火光的暖色可更偏火块本色（现沿用 LAMP 的琥珀 `0.60,0.42,0.18`）；② 雨天整体偏暗（sky 雨压暗 0.78）是否需要缓一档。

## 11. 进阶 shader + 渲染安全网（2026-09-16，全部纯渲染层）

## §12 水 / 玻璃透明（双 pass 网格 + 剔透规则，2026-09-16）

**问题不在混合，在剔除**。水体原先是不透明的（图集 alpha=1，worldShader FS 末行硬写 `fc=vec4(col,1.0)`）。
但面剔除规则只看 `mat==AIR` → **水面之下的地面根本没有顶面**。所以水一旦透明，穿透看过去就是**空洞**。
"加水透明"因此必须同时改两件事：**剔除规则** + **网格分工**。

**四步（全在渲染层 / 纯派生缓存，零漂移）**：

| 步 | 落点 | 内容 |
|---|---|---|
| 1 | `Blocks.Block.translucent` | 新标记（**纯渲染，不进仿真**）：仅 `WATER` / `GLASS` 为 true。**索引顺序不变**（确定性资产） |
| 2 | `core.world.FaceCull`（新） | 剔除规则抽成 core 纯函数：邻居 AIR/越界 → 可见；邻居**半透明且与本方块不同类** → 可见（看穿）；其余剔除。放 core 才够得着 `core.sim` 门禁（render 层在 CORE 编译阶段还不存在） |
| 3 | `Chunk` 双缓冲 | 每块两组 VAO/VBO（不透明 / 半透明），按 `translucent` 分区；**逐面与贪婪两条路径都分区**（`tools/GreedyCheck` 仍逐面等价，70356 单位面一致） |
| 4 | `Game` 透明 pass + FS | 不透明画完后再画：开混合 / `glDepthMask(false)` / **按块心距由远到近**；FS 的 `discard` 阈值 `0.5→0.02`（只留真镂空），末行改 `fc=vec4(col,tx.a)` |

**顺带修掉一个既有 bug**：`TextureAtlas.vertexColored` 未含 `WATER` → 水一直按**灰度**渲染
（`Blocks.WATER` 的蓝 58/123/208 从未生效）。已纳入 → 水恢复本色；水体 alpha 设 `0.60`。

**为什么这样"透明"是安全的**：`FaceCull` 是纯函数、网格是派生缓存、`lightGrid` 早已是派生缓存 →
**不进 `hashState`**。实测 49 道门禁全绿且所有基线指纹逐字节不变。

**已知局限 / 待本机目视**：
- 世界**关闭背面剔除** → 水中同时看到正面与背面（叠加混合），实感比 `alpha` 名义值更"实"；`alpha` 是唯一旋钮，按目视调。
- 排序粒度是**块**（块心距）而非逐面：同一块内水与玻璃相接处可能有轻微顺序错（大片水体不受影响）。
- 玻璃保持"框 + 高光、内部镂空"（图集内部 alpha=0）；它的改进是**不再遮挡其后几何**，不是变成半透明玻璃板。

## §13 无 GPU 自检：软件渲染器当「我的眼睛」（2026-09-16）

美术改动最怕「看不见 → 盲调」。本项目已有 `render.software.SoftwareRenderer`（零依赖等距 CPU 渲染器，直接出 PNG）。
本次把它接成**自检工具**：

- **面可见性与 GL 路径同源**：它不再自己写「邻居 == AIR」，而是直接调用 `core.world.FaceCull.visible(...)`。
  于是它成为那条规则的**第二个独立实现**——GL 与它必须给出同一套可见面；一处写错，另一处立刻对不上。
- **半透明方块按 `Blocks.WATER_ALPHA` 做 alpha 混合**（painter 顺序 = 先画后方）→ 「水是否真的透明、水底是否看得见」可以**出图自检**。
- **支持 alpha 覆盖做 A/B**：`-Dwater.alpha=0.30`，只影响出图比较，不改真实常量。

用法（无显示器也能跑）：

```
java -Djava.awt.headless=true -cp out render.software.SoftwareRenderer proof/x.png lake
java -Djava.awt.headless=true -Dwater.alpha=0.30 -cp out render.software.SoftwareRenderer proof/x30.png lake
```

**实测结论（看图定档，不是估的）**：`0.30` 太透（水底纹理压过水面，读成「湿坑」）、`0.85` 太实（水底被盖掉）、
**`0.60` 平衡**（既读成水，又看得到底）→ 保留 `Blocks.WATER_ALPHA = 0.60`。

**边界（必须说清，别过度信任）**：这是 CPU 平面着色 + painter 排序，**没有 GL 的着色器**
（光照 / 雾 / 块光 / 暗角 / 细节纹理），也不实现分块透明排序。所以它能判
**构图、几何、透明度量级**，**不能替代最终 GL 观感**。

## §14 纹理图集：图案尺度必须随 `TILE_PX` 走（2026-09-16 深夜）

**事故**：`TILE_PX` 从 16 提到 **64**（图集 1152×1152，每个方块面 64px）以提升细腻度，
但 `paintTile` 里的花纹**仍是 16px 时代的写法**（`x == 15`、`x - 7.5f`、`y / 15`、`x % 4`、`x / 4` …）。
后果不是"风格差异"，而是**实打实的错**（由 `tools/AtlasDump` 导出图集肉眼确认）：

| 方块 | 症状 |
|---|---|
| **LAMP** | 距离 `d` 无界 → 系数 `m` 变负 → **整块几乎全黑**，只剩左上角一小团光斑 |
| **FIRE** | `y / 15` 越界 → **下半整片全黑** |
| **GLASS** | 边框落在 1/4 处；斜高光**每 16px 一条**（一格 4 条） |
| **WATER** | 逐行噪声 → **细密横条纹**（像隔行扫描，不像水） |
| **CACTUS** | 竖棱**每 4px**（应为 ~16px，过密） |
| **STONE / SAND** | 噪声尺度太细 → 一眼读作**纯灰 / 纯米色平板** |
| **GRASS** | 草皮垂边仅 3~6px（应为 12~24px，几乎看不见） |

**修法（一次到位）**

1. **图案坐标**：`int sx = x / S, sy = y / S;`（`S = TILE_PX / 16 = 4`）。所有花纹一律用 `sx / sy` 表达——
   等价于"**回到 16px 时代的设计意图**"，但在 64px 上渲染。
2. **两层噪声**：`N = hash(sx, sy, …)` 负责**块面感**（尺度正确），`n = hash(x, y, …)` 负责
   **全分辨率微糙**（±3~8%）——后者才是 64px 相对 16px 的**真实细腻度红利**（近看不是死平面塑料感）。
3. **越界 / 负值一律钳制**：LAMP 辉光以 tile 中心为圆心 + `Math.max(0.78f, …)` 下限；
   FIRE 渐变按 `y / (TILE_PX - 1)` 归一化。**"这个式子会不会算出负数"必须显式想一遍**——黑块就是这么来的。

**自检工具**：`tools/AtlasDump` 无头导出图集全览 + 重点方块 3× 放大表
（走 `TextureAtlas.bakeAlbedoOffscreen()`，与 GL 上传**同一套代码** → 所见即所上传）。
**出图 → 看 → 改 → 再看，全程不需要 GPU。**

**红线**：图集只导出/审阅，不进 `hashState`；纹理改动不影响任何基线指纹。

**附带**：`GLFW_SAMPLES` 由 MSAA 2x 提到 **4x**（体素边缘抗锯齿，帧数有余时优先细腻度；掉帧降回 2 即可）。

## §15 自研艺术 UI（HUD 艺术通道 + UI 图集区 + 九宫格面板）（2026-09-21）

**动机**：HUD 此前全是**纯色矩形**（`addRect2D` 127 处调用）+ **位图字体**，HUD shader 是**纯色片元着色器**——无纹理、无圆角、无描边、无渐变、无噪点。本节给它加"艺术质感"，并保持默认态**逐字节等价**。

### 15.1 三层结构

| 层 | 位置 | 内容 |
|---|---|---|
| **顶点层** | `Game.addRect2D` 等 5 个发射器 | 布局 `pos3+col4` → `pos3+col4+uv2`（**7→9 float / stride 28→36**），默认 UV 填**严格纯白 tile 中心** |
| **纹理层** | `TextureAtlas` UI 区（`UI_TILE_BASE=200`，200..215） | 九宫格 9 部位 + 内高光 + 可平铺纸纹，全部**程序化烘焙**（零外部素材） |
| **片元层** | `Game.initHudShader` FS | `col × texture` + 纸纹噪点 + 暗角，由 `uArtAmt` 门控 |

### 15.2 恒等元素（零改动的关键）

新增 **`TextureAtlas.UI_WHITE_TILE = 216`**：**严格 exact 255,255,255,255**（含 gutter 全白，mip/各向异性安全）。

> ⚠️ **不能复用 `WHITE_TILE`(255)**。那张是给**远景剪影**的"**纯白微噪**"（`0.96 + 0.08*hash`），当恒等纹理用会让整个 HUD 被乘上 ~0.98 的确定性噪声。

**数学契约**：`uArtAmt=0` 且 UV 落在 `UI_WHITE_TILE` 上 → `texture()==vec4(1)` → 新 FS 输出 == 旧式 `fc=vec4(vCol.rgb, vCol.a)`。
**因此 127 处旧调用点一行都不用改。**

### 15.3 九宫格切片（`UI_NINE_SLICE = 0.25`）

角不拉伸、边单轴拉伸、中央双轴拉伸 → **描边粗细 / 圆角半径与面板尺寸无关**。这是 MC/SLG 类 UI 的标准做法。

**两条实现细节（都踩过）**：
1. **"本 tile 贴哪条外缘"必须显式建模**。用 tile 位置反推（`cx/cy`）时 `EDGE_T/B/L/R` 恒为 0 → 描边判定永不命中 → **描边整块不画**（边 tile 与中央逐字节相同）。改用显式布尔 `touchT/B/L/R`。
2. **"是否在圆角弧上"要用独立布尔**。`|cornerDist| < LINE_W` 且初值 0 → 判定**恒真** → 整片涂成描边色（视觉成大楔形）。

### 15.4 三条铁律（血泪，写进门禁 `ARTUI`）

> **① HUD FS 的 RGB 只乘 `t.rgb`，绝不能乘 `vCol.a`。**
> 旧式是 **straight alpha**（`fc=vec4(vCol.rgb,vCol.a)`）+ `blendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)`。在 FS 里预乘 → 所有 **alpha<1** 的 HUD 元素按自身 alpha **再压一次**。实测全屏 **23% 像素差 / maxΔ91**；**指纹**：minimap 面板区比值恰 `53/85 ≈ 0.62 ≈ a=0.60`。

> **② 等价性仪器的参照系不得与被测物共享假设。**
> 我最初把"参照 FS"也写成了同样的预乘形式 → 仪器**报 PASS 而真实帧全屏压暗**。参照侧必须**直接抄旧语句原文**。

> **③ 等价性场景必须覆盖 `alpha < 1`。**
> 直通 vs 预乘在 `alpha == 1` 时**输出完全相同** —— 只测 alpha=1 的仪器**抓不到**铁律①。

### 15.5 QA 旋钮与验证

- **`-Dbw.uiart=<0..1>`**：艺术层强度，**出厂 0**（严格退化）。
- **门禁 `ARTUI`**（`tools/ArtUiCheck.java`，无头零 GL，27 断言）：恒等纹理 exact 白 / 九宫格 UV 几何 / 描边受光不对称 / 方块 tile FNV 哈希重烘焙稳定 / **FS 单字面量纪律 + 恒等语义** / 默认强度边界。
- **GPU 仪器 `tools/UiArtEquiv.java`**（离屏真驱动）：默认关 × `alpha ∈ {1.0, 0.6, 0.25}` 全 `0/262144 maxΔ0`；阳性对照 `uArtAmt=1` → 184985/196608 maxΔ44。
- **全帧 A/B**：默认态截图 vs **改动前源码树**同参数截图 = **0/1024000，maxΔ 0**。
- **人眼验收**：`tools/UiTileDump` 导 UI 图集 PNG（含 alpha 棋盘）。

**红线**：全部改动在**渲染层**，`simHash=707ea72a82e0c797` 逐字节不变；`-Dbw.uiart` 不设即零影响。

## §16 大尺度占用 AO（≈ UE 的 DFAO）· 2026-09-29

**病**：world FS 里只有**顶点 AO**（`Chunk` 烘焙的 `ao/aoT/aoE`，**1 格尺度**）—— 台地立面、洞穴口、树冠下
在亮部**读不出体积**，整片梯田像一张白纸。

**方**：复用**已有的 3D 占用纹理**（`uShadowTex` / `uShadowSize` / `voxOcc()` —— 就是阴影那一套），
沿 **6 条半球方向 × 2 段步长（2.0 / 4.5 格）** 采样占用，累积遮蔽后**只乘 `skyTerm`**。
零新增 FBO / 零新增 pass / 零新增纹理。

```glsl
float voxAO(vec3 wp,vec3 n,float dist){
  float k=uAoStrength*(1.0-smoothstep(12.0,56.0,dist));   // 只在近场生效
  if(k<=0.002)return 1.0;                                  // ← -Dbw.ao=0 时恒等（逐字节零基线）
  vec3 t1=(abs(n.y)<0.9)?normalize(cross(n,vec3(0.0,1.0,0.0))):vec3(1.0,0.0,0.0);
  vec3 t2=cross(n,t1); vec3 o=wp+n*0.75; float occ=0.0;
  for(int i=0;i<6;i++){ float a=float(i)*1.0472;
    vec3 d=normalize(n*0.75+(t1*cos(a)+t2*sin(a))*0.66);
    occ+=voxOcc(o+d*2.0)*0.5+voxOcc(o+d*4.5); }
  occ*=0.1111111;                          // 1/9 = 6 方向 ×(0.5+1.0) ⇒ occ∈[0,1]
  return clamp(1.0-occ*k,0.25,1.0);        // 下限 0.25 防死黑
}
```

**三条踩过的坑（写死在这里）**：
1. ⚠️ **半球方向必须用几何法线 `nn`，不能用 `n`** —— `n` 是「几何法线 + 法线贴图」按 55/45 混合后的
   **扰动法线**，会侧偏，让半球射线斜着打回**自身方块**所在格 ⇒ **平坦地面被均匀压暗**（首版差异图上一大片红）。
   实测修正后 noon 均差 **1.92→1.67**、覆盖率 **21.8%→17.7%**，而 **maxΔ 不变（42）** ——
   正是"去掉虚假均匀压暗、保住真实局部遮蔽"的签名。
2. 起点必须**抬出自身格**（`wp + nn*0.75`），否则第一段 2.0 格从格内开始。
3. **只乘 `skyTerm`，不乘 `lampV`** —— 否则洞穴里的火把会被"大尺度遮蔽"一起吃掉（火把该照亮洞）。

**QA 旋钮**：`-Dbw.ao=<0..1.5>`，出厂 **1.0**；`0` = 恒等（与没有这一层**逐字节相同**）。

**验收（数值，不靠肉眼）**：
- **恒等**：`-Dbw.ao=0` × 4 个非雨场景 × 2 轮 = **逐字节相同**（`cmp`）。
- **净贡献**（`tools/png_diff.py`，`ao=1.0` vs `ao=0`）：

| 场景 | meanAbs(RGB) | maxΔ | >2 像素占比 |
|---|---|---|---|
| midnight | 0.27 / 0.26 / 0.69 | 20 | 12.1% |
| dawn | 3.03 / 2.72 / 2.81 | 75 | 18.2% |
| noon | 2.08 / 2.03 / 2.21 | 53 | 18.2% |
| dusk | 0.87 / 0.78 / 1.19 | 30 | 16.7% |
| night_rain | 0.20 / 0.18 / 0.48 | 17 | 8.0% |

- **方向性**：差异图**只有红（变暗）、没有青（变亮）**，且集中在**台地立面 / 凹角**；平坦开阔面为黑（不动）。
- ⚠️ **雨景不可用作 A/B 场景**：`-Dbw.rain=1` 的截图**跑两次会不同**（`noon_rain`/`night_rain` 交替漂移），
  说明演出时钟/雨相位有一处没被 QA 冻结 —— **这是既有 QA 仪器的缺陷，非本次引入**，已记为待办。

**红线**：全部改动在**渲染层**，`simHash=e7d033aec2a74d0f` **逐字节不变**；
`-Dbw.ao` 不设 = 出厂 1.0；`-Dbw.ao=0` 与改动前**逐字节相同**。

### §17 体积光轴（light shafts）· 2026-09-29

**病**：方向内散射（UE `ExponentialHeightFog` 的 DirInScattering，早已移植）**完全没有遮挡** ——
光路畅通无阻 ⇒ 树冠 / 洞口 / 山脊后方的雾**不该亮却一直亮着**，也没有光轴。

**方**（不新增 pass，约 +12 次 `texelFetch`，与 §16 AO 同量级）：
沿**视射线**取 4 个样本，每样本用**朝光源方向的 3 段长探**（4 / 12 / 28 格）采样占用，得透过率乘到 `dIns`：

```glsl
float voxShaft(vec3 wp,vec3 vdir,float dist,float amt){
  if(amt<=0.002)return 1.0;                       // ← -Dbw.shaft=0 时恒等（零基线）
  vec3 SL=normalize(uDirInscDir);                 // 当前在天上的天体（夜=月亮；不能用 uLightDir）
  float span=min(dist,24.0);
  if(span<=0.2)return 1.0;
  float lit=0.0;
  for(int i=0;i<4;i++){
    vec3 p=wp+vdir*(span*((float(i)+0.5)*0.25));
    float occ=voxOcc(p+SL*4.0)+voxOcc(p+SL*12.0)+voxOcc(p+SL*28.0);
    lit+=1.0-clamp(occ*0.3333333,0.0,1.0);
  }
  return mix(1.0,lit*0.25,amt);
}
```

**两条诊断（都值得记，规则 26.6/26.7 的实战）**：
1. **首版效果 = 0，别急着改方向** —— 用「**把返回值换成常量**」做二分：常量对照 `meanAbs=0.84 / maxΔ=40` ≫ 0
   ⇒ 证明 `dIns` 非零、**调制机制本身是通的**，问题只可能在探针。
2. 根因 = **探针太短**（原 1.1/3.0 格）：低太阳的遮挡物在**几十格之外**。改成 4/12/28 格后信号出现。
   （教训：光轴探针的**尺度要与"遮挡物的距离尺度"匹配**，不能照抄 AO 的近场半径。）

**QA 旋钮**：`-Dbw.shaft=<0..1>`（出厂 **0.70**；`0` = 恒等）；
配套相机朝向 `-Dbw.yaw` / `-Dbw.pitch`（**拍光轴必须先让相机朝太阳**，否则永远拍不到）。

**验收**：
- **恒等**：`-Dbw.ao=1 -Dbw.shaft=0` × 4 个非雨场景 = 与光轴补丁前**逐字节相同**。
- **信号定位**（先量化哪里有信号，再决定拍什么）：扫 8 个 yaw × 2 相位（`-Dbw.dirinsc=6` 放大内散射当探针），
  **只有 `phase=0.78`(黄昏) + `yaw=90`（相机朝太阳）有信号**：`meanAbs=0.575 / maxΔ=37 / 9.6% 像素`；
  其余视角 ≈0 —— **开阔地形没有遮挡物，物理上本就不该有光轴**（不是 bug）。
- **方向性**：差异图**纯红（只有变暗、没有变亮）**，形状是**从右侧延伸的楔形** = 山脊挡住太阳
  ⇒ 那段空气的内散射被削弱。

**诚实边界**：本场景**没有茂密树冠**，所以它读起来是"柔和的雾梯度"而非戏剧性光柱；
它真正的价值是**修掉一个既有不正确**（内散射此前完全不遮挡）。要更明显的效果需另有遮挡密集的场景。

**红线**：纯渲染层；`simHash=e7d033aec2a74d0f` **逐字节不变**；`-Dbw.shaft=0` 与改动前**逐字节相同**。

## §18 观感四件套 + 两个仪器缺陷（2026-09-29）

本批一口气做四件事（dither 修色带 / A2C 修镂空边缘 / 自动曝光 / 森林 QA 场景），
并顺带挖出**两个既有仪器缺陷**。全部纯渲染层。

### 18.1 `-Dbw.forest` 森林 QA 场景（让"光轴"终于可测）

**为什么必须造场景**：§17 的光轴在开阔地形里"零信号"——不是实现错了，是**物理上就没有遮挡物**。
自然地形是 `SCATTER_TREE_DENOM=250` 的稀疏散树，取景框里根本凑不出树冠。
故加一个 QA 场景开关（照 `-Dbw.lamp` / `-Dbw.edgescene` 的范式）：在出生点前方整平林地并种
**3 格间距的确定性密林**（树高 5~8 由整数哈希给，球状树冠半径 2；不碰任何 RNG）。
不设该属性时世界逐字节不变。

**结果**（`dusk` + `yaw=180` + `pitch=20`，相机朝太阳）：

| 场景 | meanAbs(shaft 0 vs 1) | maxΔ | >2 像素占比 |
|---|---|---|---|
| 开阔地形（§17，最强视角） | 0.575 | 37 | 9.6% |
| **密林（本批）** | **1.03** | **60** | **7.6%** |
| 密林其它 7 个朝向 | ≤0.25 | ≤57 | ≤4.5% |

**诚实边界**：信号确实变强了（0.58→1.03），但差异图形状仍是"山脊/树冠遮挡 ⇒ 那段空气变暗"的**楔形**，
**不是**电影里的**光柱**。要真正的 god-ray 需要"从太阳屏幕位置做径向模糊"的**屏幕空间 pass**——
那是另一个特性，本批没做。

### 18.2 dither 修色带（`grade()` 末尾 ±0.5 色阶）

ACES + 分级后的暗部/天空是大块渐变，8 bit 输出上会出现色带。在 `grade()` 末尾叠一层
`(h31(gl_FragCoord.xy)-0.5)*uDither`（默认 `1/255`）。

**⚠️ 抖动源必须与帧无关**：只能用 `gl_FragCoord`（同像素恒同值），**绝不能用 `uTime`**——
后者会让同一像素逐帧变化，当场毁掉 A/B 仪器契约。

**验收（数值判读，不靠肉眼）**：抖动修色带的正确签名是**"同色长段被打散"**，不是"像素差变大"。
故统计天空带内**完全相同 RGB 的连续段**：

| 场景 | 最长同色段 | ≥12px 的段数 | 平均段长 |
|---|---|---|---|
| noon dither=0 | 141 | 722 | 2.19 |
| **noon dither=1** | 141 | **146（−80%）** | **1.51** |
| dusk dither=0 | 210 | 642 | 2.74 |
| **dusk dither=1** | 210 | **136（−79%）** | **1.69** |

⚠️ **别用"相邻像素硬跳变数"当指标**：抖动会新增 ±1 噪点，该指标反而**升**（noon 6668→7556），
一度让我误判"dither 让色带更严重"。**指标选错 = 结论反了。**

### 18.3 A2C：修 `discard` 镂空边缘（实现完成，本环境**无法验收**）

`discard` 是逐像素二值的，MSAA 样本共享同一个片元着色结果 ⇒ 树叶/草的镂空边缘永远硬台阶。
做法：片元里用 **mip1 的 alpha** 估覆盖率（atlas 烘焙时 mip 的 alpha 走 4-tap 线性平均 ⇒ 天然是分数），
写进 `fc.a`，配合 `glEnable(GL_SAMPLE_ALPHA_TO_COVERAGE)`。只对不透明材质生效
（`tx.a>0.98`）⇒ 大块半透明面不会被 A2C 打成噪点（A2C 的经典副作用）。

**⚠️ 无法验收（诚实登记）**：A2C 只在 MSAA 开启时存在，而本机 **`GL_SAMPLES(actual)=0`**——
请求 `GLFW_SAMPLES=4`，驱动只给 0（同一台机上单独建窗却真能拿到 4，且逐次运行结果还不稳定）。
已加 `-Dbw.msaa=<n>` / `-Dbw.show=1` 两个旋钮和 `tools/MsaaProbe.java`（**每条用例单独一个 JVM**——
初版把多用例串一个进程，第二个之后全返回 0，说明 GLFW 状态会跨窗口泄漏）留给有交互会话的机器复验。
**已验证的只有**：`-Dbw.a2c=0` 与 `=1` 在 MSAA=0 下**逐字节相同**（即 A2C 在无 MSAA 时是真 no-op）。

### 18.4 自动曝光（眼适应）· 与逐字节 A/B **根本冲突**

**实现**：`glBlitFramebuffer` 把默认帧缓冲降到 `6×4`（顺带 resolve MSAA）→ `glReadPixels`
24 像素 → Rec.709 亮度平均 → `want=(0.55/lum)^0.5` 夹 `[0.80,1.35]` → 乘进 `grade()` 之前的
`uExposure`。运行时稀疏测光（每 8 帧）+ 平滑（`0.06/帧` ≈ 1 秒眼适应）。

**标定**（`-Dbw.explog=1` 实测"曝光=1 时"的帧缓冲平均亮度）：

| 场景 | noon | dawn | dusk | midnight | 密林黄昏 | 夜雨 |
|---|---|---|---|---|---|---|
| 实测亮度 | 0.583 | 0.445 | 0.343 | 0.283 | 0.091 | 0.207 |

取 TARGET=0.55 ⇒ **正午 exposure≈0.97（常规观感不动）**，越暗才越提亮。

**⚠️ 契约冲突（本批最重要的发现）**：自动曝光把**画面自己**反馈进一个**全局乘子**
⇒ 帧缓冲里任何 ≤1 LSB 的抖动都被放大成可见差异。实测：默认开启时 `dusk/dawn/midnight`
**两次截图不一致**（`noon` 却一致）。这与"无头截图必须逐字节可比"**根本冲突**。
因此定案：**QA 下默认不做自适应**（`uExposure≡1`，仪器契约不受损）；要对比就用
`-Dbw.expofixed=<乘数>` 给一个**常数**曝光。**自适应本身只在运行时生效，其验收只能靠实机观察**——
本批**不假装**仪器测过它。

**真凶诊断过程（值得记的两次假象）**：
1. 第一版用**绝对式** `want=TARGET/lum`，日志显示亮度在 `0.59→0.36→0.52→0.38…` **来回震荡**
   —— 因为测光测的是"曝光之后的画面"，形成反馈环。改为幂次式 `(T/lum)^0.5` 压平增益。
2. 第二版改成"世界稳态首帧锁存"，但 `midnight` 仍不一致 ⇒ 锁存判据比截图稳态**少算了
   `meshBuilder.inflight/ready`**（锁到"网格还没传完"那帧）。**"稳态"是要逐条对齐的判据，不能凭感觉写。**

### 18.5 顺带修掉的两个**既有仪器缺陷**

1. **雨景截图不可复现（已修）**：`rainSmooth` 是**每帧指数平滑**（`*0.04`）且无 `qaFrozen` 保护
   ⇒ 结果取决于"稳态触发前跑了几帧"，而帧数随机器负载波动（实测 `noon_rain` / `night_rain`
   交替漂移，4 个非雨场景却稳定）。修法：QA 下直接取目标值（等价于已收敛）。
   **修后 `-Dbw.rain=1` 连拍两次逐字节相同。**
   教训：**凡是"跨帧累积"的量，QA 都必须有确定性终值**——本作已为此制过 4 次同型补丁
   （仿真/演出时钟/泛光记忆/失焦遮罩），这是第 5 次。
2. **"MSAA 4x 抗锯齿"曾经是一句谎话（已暴露）**：代码注释写"MSAA 4x 抗锯齿"，但实机
   `glGetInteger(GL_SAMPLES)` 读回 **0** ⇒ 这句注释一直在说谎，而且**没人会发现**。
   现在 `initGL` 把**真实采样数**写进 `render_diag.log`（`GLFW_SAMPLES(req)=… GL_SAMPLES(actual)=…`），
   顺带把 `dither`/`a2c` 的实际取值一起打印。**"请求的参数"与"拿到的参数"必须分开记录。**

### 红线
纯渲染层：`-Dbw.dither=0` / `-Dbw.a2c=0` / `-Dbw.exposure=0` / 不设 `-Dbw.forest` 时
世界与画面与改动前一致；仿真指纹 `simHash` 逐字节不变（全量构建校验）。

## §19 god-ray：屏幕空间体积光（"光柱"的正解）· 2026-09-30

### 19.1 为什么 §17 不够
§17 的体素光轴是**逐像素几何近似**（沿视射线探 3D 占用得透过率，乘到内散射上）。它给出的是
"被遮挡的雾变暗"——**形状对、但不成束**（实测差异图是楔形，不是光柱）。
真正的光柱来自**沿视线的累积散射**，经典做法就是屏幕空间径向模糊
（GPU Gems 3, *Volumetric Light Scattering as a Post-Process*）。

### 19.2 实现（三段，**放在泛光之前**）
```
世界+实体 ──blit 降采样──▶ godSrc(½res) ──径向模糊×24──▶ godOut(¼res) ──加性合成──▶ 默认帧缓冲
```
- **必须在泛光之前**：泛光之后灯火/岩浆的辉光会被掩码当成"光源"拉成假光束（方向还被拽向太阳）。
- 光源屏幕位置：`(sun|moon 方向) → view → proj` 投影取 UV。
- 掩码 = `pow(clamp((l-floor)/(1-floor),0,1), pow)`，`l` = 该像素的 max(RGB)。
- 输出乘 `(1-scene)`：已经亮的地方不再叠加（免得太阳盘糊成白饼）。
- 关掉即恒等：`-Dbw.godray=0` ⇒ 整段跳过（实测与改动前**逐字节相同**）。

### 19.3 三个会把效果做废的坑（都实测踩过）

**① 光源筛选：必须"在地平线上 **且** 在镜头前"** —— 不能照抄 §17 的"太阳在上就用太阳"。
实测黄昏朝 `yaw=180` 时"在天上"的那个天体在**相机背后**（投影 `w<0`）⇒ 效果恒为 0，日志却只显示
"SKIP behind"，极易被误读成"实现有 bug"。正确判据：在**地平线以上**的天体里取**与相机前向最同向**的那个。

**② 掩码不能用"阈值 + 宽 smoothstep"**（本批最大的坑）。显示域里**太阳盘(1.0) 与亮天空(0.72~0.85)
只差 0.15~0.28**，0.30 宽的 ramp 会把整片天空一起算成光源 ⇒ 结果是"整屏蒙一层雾"而不是光束。
实测**悬崖式**：阈值 0.72 → meanAbs 4.79（55% 像素被改，雾）/ 0.85 → 0.18（几乎没了）——
中间没有可用的档位。改成**幂次掩码**后连续可调、形状正确：

| 掩码幂次 | meanAbs | maxΔ | 被改像素 |
|---|---|---|---|
| 3 | 3.211 | 43 | 50.1%（雾） |
| **6（出厂）** | **0.804** | **19** | **8.9%** |
| 10 | 0.187 | 7 | 2.6% |
| 16 | 0.063 | 5 | 1.2% |

⚠️ 顺带一条**证伪**：我原以为"1/4 分辨率把太阳盘平均掉"是主因，于是把源提到 **1/2 分辨率**——
结果数字几乎不变（4.79 → 4.82）⇒ **主因是掩码形状，不是分辨率**。（分辨率仍然保留 ½，因为它让
盘面峰值更稳，但它不是决定性的那一环。）**"换个参数再测"之前，先确认你改的是不是真因。**

**③ 光源不在画面里就没有光柱**（同 §17 的教训，这里更硬）：太阳在地平线下 / 在相机背后 /
远出画 → 整段跳过。实测这三种情况 **meanAbs 全 0.000**（无假阳性）。

### 19.4 信号定位（先算，别瞎试）
`-Dbw.godlog=1` 会打印天体的屏幕 UV。扫 yaw 后发现**白天**可用取景：`phase=0.35,yaw=0` → UV(0.36,0.59)、
`phase=0.65,yaw=180` → UV(0.64,0.59)。用 `-Dbw.godconst=<v>` 做**常量对照**（直接输出常量、绕过纹理/掩码）
可二分出"pass 没跑"还是"掩码没找到光源"——实测常量 0.2 → meanAbs 42.7（pass 与加性混合都正常）。

### 19.5 验收
| 项 | 结果 |
|---|---|
| 恒等 | `-Dbw.godray=0` 与上一批**逐字节相同**（noon/dusk/midnight 3/3） |
| 可复现 | 同参数连拍两次**逐字节相同** |
| 净贡献（day65） | meanAbs **0.804** / maxΔ **19** / 8.9% 像素 |
| 形状 | 差异图 = **从太阳位置向外发散的放射状条纹**，太阳核心处有暗洞（`1-scene` 生效） |
| 假阳性 | 光源在背后 / 出画 ⇒ **0.000**（3/3） |
| 构建 | `88/88 *_EXIT` 全 0、`AUDIT 0 FAIL`、`simHash` 不变、`SHADERCHECK PASS (15 programs)` |

### 19.6 诚实边界
这是**屏幕空间散射**（halo / veiling glare）。太阳**完全暴露**时它读作"围绕太阳的光晕"；
只有太阳**被枝叶/山脊部分遮挡**时才读作**放射状光束**——遮挡来自掩码本身（被挡住的太阳像素是暗的，
于是射线上出现明暗交替），**这正是屏幕空间做法的天然优势**，也是它的边界：
它无法照亮"没有任何光源像素可见"的方向。

**红线**：纯渲染层；`-Dbw.godray=0` 与改动前逐字节相同；`simHash` 不变。
QA 旋钮：`-Dbw.godray`（增益，0=关）、`-Dbw.godthresh`（掩码地板，出厂 0.60）、`-Dbw.godpow`（幂次，出厂 6）、
`-Dbw.godlog=1`（打印天体屏幕 UV）、`-Dbw.godconst`（常量对照探针）。
